# P2-45-R4.3 — Device-Test Logging & Diagnostics

## Scope
Prepare FilterKit for RootHide device testing by separating user-visible activity from developer diagnostics, improving privacy controls, adding bounded retention/export, and providing a read-only Helper audit collector.

## Changes
- Reworked `RuntimeEventLogger` into two separate persisted projections:
  - `runtime.jsonl`: structured developer events with severity, module, event name, trace/session context and bounded attributes.
  - `activity.jsonl`: minimal user history containing only timestamp, level, event name, localized title and sanitized detail.
- Added redaction for sensitive attribute keys, absolute filesystem paths, emails, UUIDs, app identifiers and long hashes in user-facing details.
- Developer log messages redact known absolute path roots; sensitive attribute values (tokens, credentials, paths, CDHashes, provisioning profile/private-key fields) are replaced with `[redacted]`.
- Added 1 MiB developer log and 256 KiB activity log bounds, one previous generation for each, compatibility reading for the previous Activity Event schema, and separate clear operations.
- App log directory/export files use restrictive permissions (0700 directory, 0600 files).
- Added Settings → Developer Logs: recent-event preview, log size, export via iOS share sheet, and clear confirmation.
- Added Helper status success/failure events after the actual request result is known.
- Added operation outcome events at the actual Helper commit/receipt boundary for App activation and additional-App association. Unknown transport outcomes are logged as `unknown`, not falsely marked failed or successful.
- Added runtime resource context (FilterKit version/build and iOS version) to developer events.
- Added a RootHide-side read-only Helper audit collector. It requires root, validates root-owned 0600 regular audit files, rejects symlinks, and writes copies outside JBROOT. It does not start/stop Helper or mutate JBROOT.
- Kept Helper audit separate from App logs. Helper audit remains root-owned and 0600; it is not silently copied into the App diagnostic export.
