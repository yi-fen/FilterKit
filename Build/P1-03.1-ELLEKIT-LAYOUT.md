# P1-03.1 — ElleKit 安装状态与布局识别

## 范围

只读识别 ElleKit 的安装布局与安装状态。不执行 dpkg 命令、不修改设备文件、不验证运行时注入、不读取 Mach-O 版本或 CDHash（这些属于后续阶段）。

## 已实现

- 独立 `ElleKitInstallationState`：`installed`、`suspected`、`notFound`、`inaccessible`。
- `ElleKitLayoutEvidence` 逐项记录路径、类型、是否存在、是否可读、是否符号链接，以及主 dylib 的 Mach-O magic 初筛结果。
- 探测主 dylib 候选：`Library/TweakInject/ellekit.dylib`、`Library/TweakInject/libellekit.dylib`、`usr/lib/libellekit.dylib`。
- 探测配套 dylib：`Library/TweakInject/pspawn.dylib`、`usr/lib/TweakInject/pspawn.dylib`。
- 探测兼容链接、loader、启动 LaunchDaemon plist 和 `var/lib/dpkg/info/ellekit.list`。
- 保留 dpkg `status` / `status-old` 的当前库与回退库区分；只有 `Status: install ok installed` 才作为已安装包元数据。
- 主 dylib 必须可读且具备已知 Mach-O magic 才作为主二进制强信号；单独的 plist、loader、兼容链接或配套 dylib 只产生 `suspected`。
- 所有路径证据写入诊断模型，不以路径存在直接推断当前进程已加载 ElleKit。

## 状态规则

| 状态 | 本阶段判定 |
|---|---|
| `installed` | 当前 dpkg status 有已安装 ElleKit 记录，或主 dylib 通过 Mach-O magic 初筛 |
| `suspected` | 发现部分布局/包碎片，但没有已验证主 dylib |
| `notFound` | 没有观察到任何已知布局证据 |
| `inaccessible` | status 文件明确存在但不可读，且没有其他足以确认的安装证据 |

注意：Mach-O magic 只是文件格式初筛，不代表架构、load command、签名或 CDHash 已验证。dpkg 与主 dylib 相互矛盾时，证据状态会保留为不一致，不能简单隐藏矛盾。
