# FilterKit R4.3 Device Logging Guide

## User activity history
Open **Settings → Activity History**. This view shows completed user-relevant events only. It intentionally omits internal identifiers and raw diagnostic attributes.

## App developer diagnostics
Open **Settings → Developer Logs**:
1. Review the recent diagnostic event preview and current log size.
2. Tap **Export Developer Logs** to share `FilterKit-Developer-Logs-*.jsonl`.
3. Clear developer logs separately from user activity history when requested.

The App log directory is inside the FilterKit application sandbox:
- `Library/Application Support/FilterKit/Logs/runtime.jsonl`
- `Library/Application Support/FilterKit/Logs/runtime.previous.jsonl`
- `Library/Application Support/FilterKit/Logs/activity.jsonl`
- `Library/Application Support/FilterKit/Logs/activity.previous.jsonl`

The App developer export is privacy-redacted. It does not include the privileged Helper audit file.

## Privileged Helper audit (RootHide device)
The Helper writes a separate root-owned audit stream:
- `$JBROOT/Library/FilterKit/Helper/audit.jsonl`
- `$JBROOT/Library/FilterKit/Helper/audit.jsonl.1` through `.3`

These files are expected to be root-owned and mode 0600. They can contain peer identity and operation metadata and should be treated as sensitive developer evidence.

Run as root on the device:

```sh
Build/scripts/p245_r4_3_collect_helper_audit.sh <absolute-JBROOT> <absolute-output-directory>
```

The output directory must be outside JBROOT. The collector rejects symlinks, non-regular files, unexpected owner or permissions, and prints SHA-256 for each copied file. It does not start, stop, bootstrap, or otherwise modify Helper; it only reads the existing audit files and writes copies to the requested output directory.

## When sending logs for debugging
- Prefer the App developer export first.
- Send Helper audit only when specifically requested for an IPC/Helper issue.
- Do not post raw Helper audit publicly; it is more sensitive than the user activity history.
- Include the FilterKit build version and iOS version separately when reporting a device issue.
