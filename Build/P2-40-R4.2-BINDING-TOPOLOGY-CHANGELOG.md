# P2-40-R4.2 — Binding Topology Domain Model

## Scope

This increment adds a canonical, testable domain model for the product terminology:

- **Fixed Owner** (`fixedOwner`): the immutable source App identity. It cannot be removed, but its activation can be turned on/off.
- **Additional App Association** (`additionalAssociationsOnly` / `additionalAssociations`): extra App relationships. Each relationship has its own enabled bit and can be removed only after it is disabled.

## Implemented

- Added `Sources/Core/Models/PluginBindingTopology.swift`.
- Added `Tests/UnitTests/PluginBindingTopologyTests.swift`.
- First successful import decisions map to a Fixed Owner topology, enabled by default.
- Later import decisions map to an association-only topology, with the importing App associated and enabled by default.
- Adding an association later from Plugin management defaults it to disabled; import-time defaults remain enabled as specified by the batch policy.
- Fixed Owner activation can be toggled without changing or removing the owner identity.
- Additional associations can be toggled; removal is rejected while enabled.
- Validation rejects invalid Bundle IDs, duplicate associations, and representing the fixed owner a second time as an additional association.

## Deliberate non-scope / integration boundary

This increment is the domain-model foundation only. It does **not** yet change the persisted FilterKit manifest schema, backup schema, Helper IPC request format, Helper first-install bootstrap, Helper authorization/attestation, deployment transaction, or production release gates. Existing production flows remain on their existing schema-3 hard-bound contract. Do not use this model to authorize a real deployment until the subsequent manifest/backup/Helper integration phases are complete.

No production Gate was opened or modified.
