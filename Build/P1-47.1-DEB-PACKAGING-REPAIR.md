# P1-47.1 — DEB Packaging Output Repair

## Scope

Remove the unconditional CI block for DEB output and add a validated Debian
package assembly step. This phase does not run Xcode compilation in the local
work session; the CI workflow will compile when the user explicitly runs it.

## Changes

- `Build/Scripts/ci-build.sh`: DEB and Both are no longer rejected by a hardcoded
  exit. The script requires `dpkg-deb`, rejects unverified Rootless packaging,
  and invokes the package assembler after the app product is copied.
- `Build/Scripts/package-deb.sh`: creates `cn.yfen.filterkit_<version>-1_iphoneos-arm64.deb`
  from the already-built `FilterKit.app`; checks bundle ID, version, build,
  executable, package control fields, and app payload.
- `.github/workflows/build.yml`: installs Homebrew `dpkg` only for DEB/Both jobs.
- `Build/Packaging/README.md`: records package layout and the helper boundary.
- `Build/P0-07-GITHUB-ACTIONS.md`: updates the previously blocked DEB status.

## Package layout

RootHide only, using the non-Rootless package layout documented in
`Build/P1-03-ELLEKIT-INSPECTION.md`:

`/Applications/FilterKit.app`

Package architecture: `iphoneos-arm64`. Debian version: app marketing version
plus packaging revision `-1` (currently expected to be `1.0.0-1`).

## Signing

No Apple Developer certificate is needed to create a DEB. The app build remains
unsigned (`CODE_SIGNING_ALLOWED=NO`), consistent with the existing CI policy.
The DEB is a Debian archive, not an IPA and not an Apple-signed distribution.

## Explicit limitations

- No Xcode build was run in this phase.
- No installable production DEB was emitted locally because this workspace has
  no compiled `FilterKit.app` product. The CI pipeline will create the DEB after
  its normal Xcode build step.
- The package deliberately excludes the privileged helper and launch daemon;
  those are not yet approved for production installation/activation.
- Rootless DEB output remains blocked pending a verified Rootless package layout.
