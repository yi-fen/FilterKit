# P1-03.3 — ElleKit Profile fingerprint registration and matching

## Scope

This phase adds a read-only, data-driven FilterKit Profile registry and a deterministic matcher. It does not install, modify, sign, inject, or otherwise change ElleKit or jailbreak files.

## Profile model

Each `ElleKitProfileRecord` declares:

- Profile identifier, environment and lifecycle status.
- Allowed Debian package versions.
- Package identity constraints: package name, architecture, maintainer, origin and homepage.
- One or more accepted binary identity tuples containing install name, `LC_UUID`, CDHash and optional architecture constraints.

A profile marked `reference-baseline` is descriptive only. It is not eligible to produce `matched`. Only a `verified` profile with at least one complete binary fingerprint pin can produce `matched`.

## Shipped baseline

`Build/Profiles/profiles.json` is mirrored into the app bundle as `Resources/ElleKitProfiles.json`; `ElleKitProfileRegistry.loadBundled()` loads it at runtime. It contains the RootHide / Dopamine ElleKit `1.2-3` reference baseline associated with commit `16e3e7e`. It currently records package name, arm64e package architecture and package version only. No verified `installName + LC_UUID + CDHash` tuple has been registered. Consequently, a device with that package version is classified as `unknownFingerprint`, never as `matched` or commit-verified.

The Rootless entry remains explicitly unverified and is not treated as a supported Profile.

## Match outcomes

- `matched`: installed package identity, allowed package version and a complete pinned binary identity tuple all match.
- `versionMismatch`: package identity constraints match, but the Debian package version is outside the Profile's allowed versions.
- `identityMismatch`: a known package identity field or complete binary fingerprint conflicts with the Profile.
- `unknownFingerprint`: no Profile exists for the environment, or the matching reference Profile has no verified binary fingerprint pins.
- `unverifiable`: package metadata or required pinned fingerprint fields are unavailable.
- `environmentNotSupported` / `notEvaluated`: the environment is unsupported or evaluation is not applicable.

Missing evidence is never silently treated as a match. A missing CDHash is not considered a mismatch; it yields `unverifiable` when a Profile requires it.

## Integration

`ElleKitInspector` accepts an injected registry and otherwise loads the bundled registry (falling back to the conservative built-in reference record if the resource is unavailable). It delegates Profile evaluation to `ElleKitProfileMatcher` after package and Mach-O fingerprint collection. `candidateProfileIdentifier` identifies the candidate/reference Profile used for the result, even when the final outcome is unknown or unverifiable. `commitVerified` is true only for a full `.matched` result.

The existing dpkg package version and Mach-O linker versions remain separate. Layout evidence is still supporting evidence and is not used as a substitute for package or binary identity.

## Validation and limitations

- Profile registry JSON schema and duplicate identifier validation are implemented.
- Offline matcher fixtures cover all five primary outcomes, including a positive match using a synthetic test-only pinned profile.
- The shipped reference Profile intentionally cannot match until real, verified binary identity pins are collected.
- CDHash platform collection remains an injected provider contract from P1-03.2; this phase does not invent a CDHash implementation.
- Full Xcode/iOS SDK build and jailbreak-device validation have not been performed in this environment.
