# P1-02.1 — RootHide / Rootless identification enhancement

## Scope

Read-only enhancement of P1-02. No jailbreak files are written, no helper is launched, and no injection configuration is changed.

## Included

- Scans both `/var/containers/Bundle/Application` and `/private/var/containers/Bundle/Application` for RootHide candidates.
- Canonicalizes candidate paths and merges aliases before ambiguity decisions.
- Adds a conservative `.jbroot-` + 16 hexadecimal non-zero suffix format gate. This does **not** claim checksum validation; the jbrand checksum algorithm remains gated on verification against the target Dopamine implementation.
- Adds optional runtime `dlopen` / `dlsym` discovery for libroot's `libroot_get_jbroot_prefix`, `libroot_get_root_prefix`, and `libroot_get_boot_uuid` functions.
- Treats libroot as evidence, not authority: returned JBROOT must pass the same filesystem checks, and conflicting valid roots remain ambiguous.
- Introduces `JailbreakPaths` to keep JBROOT and rootfs distinct. `jbrand` is reserved and remains nil until a verified RootHide devkit adapter is integrated.
- Records Rootless `/var/jb` symlink characteristics using `lstat` on Darwin platforms.

## Important limits

- The exact RootHide `.jbroot` marker-link location/semantics were not specified sufficiently to hard-code a marker path. The resolver records whether a candidate itself is a symlink and its canonical target; this is not represented as full marker-link validation.
- The checksum portion of jbrand is intentionally not guessed or copied from an unverified legacy implementation.
- `rootfs` from libroot is optional. No default `/rootfs` is inferred for RootHide.
- RootHide devkit `jbroot()`, `rootfs()`, and `jbrand()` are not linked in this phase. The path translator protocol is a boundary only.
- API availability and sandbox visibility must be validated on supported Dopamine devices. Offline tests use filesystem fixtures and do not emulate libroot.

## Acceptance behavior

- One unique structurally valid canonical root may be selected.
- Multiple distinct valid roots remain unresolved.
- Missing libroot falls back to filesystem discovery.
- A libroot path that fails structural checks is not selected.
- This phase never authorizes deployment; capability flags remain fail-closed.
