# P2-45-R4.4 — Plugin Inventory Association & Provenance Repair

## User-reported issues addressed

- Third-party plugins installed by Sileo/Zebra/Irisin appeared as standalone plugins.
- Associated Apps were not shown in the Plugin list.
- The list repeated the `.dylib` filename below the display name.
- The list displayed a disclosure chevron that the user wanted removed.
- Source attribution remained unknown.
- Team Identifier was not clearly surfaced.
- ElleKit compatibility displayed a missing verified fingerprint without explaining the reason.

## Evidence from the uploaded developer log

The 2026-11-28 session recorded four plugin inventory entries. The scan metrics showed `plugin_plist_reads=4`, `manifest_reads=0`, and association snapshot consumption after the App inventory became available. Earlier legacy records only reported that four plugin records were found and did not include per-plugin ownership evidence.

The code path explains the association display regression: `PluginListStatus` derived its App list from FilterKit manifest hard/soft bindings only. A third-party package with a valid ElleKit `Filter.plist` `Bundles` target but no FilterKit `.fk.json` manifest therefore produced an empty App list and was presented as standalone. The scanner already parsed `Filter.plist`, but the third-party list row did not use its target data.

The uploaded log does not prove why any particular package failed dpkg ownership matching. R4.4 therefore adds explicit per-record evidence provenance and broadens read-only discovery of common RootHide/rootless dpkg database roots rather than claiming an unproven single cause.

## Changes

1. Added `PluginTargetDisplay`, a read-only projection of third-party `Filter.plist` targets:
   - `Bundles = ["*"]` → global/all-App target.
   - Explicit `Bundles` → display matching installed App names, falling back to Bundle IDs.
   - `Executables`/`Classes` without `Bundles` → rule-based target.
   - Missing/unparseable target metadata → “not recognized”, explicitly not “standalone”.
2. Kept FilterKit Fixed Owner and Additional Associations separate from third-party Filter.plist targets. Third-party targets do not become FilterKit bindings and do not gain management permissions.
3. Extended read-only dpkg database root discovery to include RootHide nested `var/jb`, private, `/var/jb`, `/var/rootless`, and conventional root locations. The provider still selects one readable database and never merges package databases or invokes dpkg.
4. Persisted package version and package-evidence source into each scan record. Source labels now distinguish a matched dpkg file-owner record, readable database with no owner match, and unavailable database.
5. Exposed Mach-O CodeDirectory Team Identifier as a structured detail field. Missing Team ID is reported as absent/unreadable; it is never guessed from CDHash or Bundle ID.
6. Added aggregate scan diagnostics for package ownership, manifest presence, target parsing, missing Team ID, and missing binary fingerprint. No file paths, Bundle IDs, or hashes are added to these aggregate counters.
7. Removed the dylib filename from the Plugin list row. The detail view still retains exact filenames for diagnostics.
8. Replaced the list `NavigationLink` disclosure row with a plain button opening the same detail view in a sheet, removing the right-side chevron while preserving access to details.
9. Clarified the ElleKit status label: missing verified fingerprint means no verified device binary fingerprint (install name + UUID + CDHash) is available. No fingerprint was fabricated and the built-in reference profile remains unverified.

## Security and product boundaries retained

- Inventory remains read-only.
- Sileo/Zebra/Irisin plugins remain third-party/package-manager-owned and read-only.
- dpkg evidence identifies package ownership, not which frontend/store UI performed installation. R4.4 does not claim to distinguish Sileo from Zebra or Irisin when the shared dpkg database contains no frontend provenance.
- A `Filter.plist` Bundle target is a runtime target projection, not a FilterKit Fixed Owner.
- No third-party plugin is adopted, migrated, enabled, disabled, replaced, or uninstalled.
- Helper is still not connected; no Helper attestation or production write path is enabled.
