# P2-45-R4.2 — Signed Artifact & RootHide Runtime Verification

## Added

- `Build/scripts/p245_r4_2_verify_signed_artifacts.sh`: macOS-only, read-only cross-verification of a previously signed FilterKit.app and standalone Helper. It checks both code signatures, identifiers, Team ID equality, CDHash format, the exact Helper CDHash embedded in App trust JSON, trust generation, root UID/GID scope, and the App provisioning profile identity.
- `Build/scripts/p245_r4_2_device_runtime_probe.sh`: explicitly configured, root-authorized, read-only RootHide runtime snapshot for the deployed Helper binary, socket, and exact launchd label. It does not bootstrap, bootout, kickstart, send IPC, or mutate JBROOT.
- `Build/scripts/p245_r4_2_static_audit.py`: static safety and coverage audit.

## Deliberately not changed

- No production Swift identity or IPC code changed. The existing `SecTaskCopyValueForEntitlement("com.apple.developer.team-identifier")` lookup must be proven on a real iOS process; it is not safe to replace with Team ID inferred from CDHash or a caller-supplied field.
- No Xcode signing configuration changed. Helper target `CODE_SIGNING_ALLOWED: NO` remains an unsigned Xcode build followed by the separately signed artifact flow defined in R4.1.
- No launchd template or production execution gate changed.
- No device installation, launchd operation, IPC request, or JBROOT write was performed.

## Required device evidence

1. Run the R4.1 Apple build on macOS with an explicitly selected signing identity and installable profile.
2. Run the R4.2 artifact verifier against that exact `.app` and Helper output; retain the full report and hashes.
3. Install/deploy only through the separately reviewed RootHide test procedure. Do not enable the disabled launchd template by editing it ad hoc.
4. On device, run the read-only runtime probe with paths confirmed from the signed provisioning manifest.
5. Launch FilterKit through the normal user path and invoke its existing Helper connection/attestation diagnostic. Export the diagnostic log. A successful transport round-trip must show kernel peer credentials, Audit Token stability, CDHash, signing identifier, and Team ID. `peer_team_identifier_unavailable` is a hard failure.
6. Confirm the Helper's launchd job lifecycle and socket permissions from device evidence. Any mismatch blocks further testing.
7. Only after the above, proceed to the separately authorized D1–D12 R4 device matrix. No real plugin write is part of R4.2.
