# FilterKit package output

## RootHide DEB

The RootHide release package follows the R16.1 RootHide rootfs profile. Package identity, architecture, payload layout, register path, dependencies, and control metadata live in `Build/Config/DEB/roothide.env`; `Build/Scripts/package-deb.sh` sources that profile and only assembles, signs, validates, and archives the package.

- Debian `Architecture: iphoneos-arm64e`
- Payload `Applications/FilterKit.app` (installed as `/Applications/FilterKit.app`)
- Dependencies `firmware (>= 15.0), ellekit`
- Registration-only `postinst` invokes `uicache -p /Applications/FilterKit.app` on a best-effort basis.
- The app bundle is signed with the R16.1 ldid signing flow. Nested Mach-O images are signed before the main executable. Signature structure, CDHash extraction and embedded entitlement equality are checked before and after packaging.

The DEB architecture field is package-manager metadata, not an instruction to build an arm64e-only Mach-O. The app binary is separately checked for an `arm64` or `arm64e` slice. The current CI maps both `arm64` and `arm64e` device labels to the supported arm64 app slice while keeping RootHide DEB metadata at `iphoneos-arm64e`.

Build with GitHub Actions: `Environment=RootHide`, `Configuration=Release`, `Package=DEB` (or `Both`). The output is placed under `Build/Output/RootHide/`.

Unsigned structure fixtures can only be generated by explicitly setting `ALLOW_UNSIGNED_STRUCTURE_PACKAGE=1`; their filename contains `.unsigned-structure.deb` and they are not installable release packages.

## Signature and device-acceptance boundary

The R16.1 entitlement plist contains candidate private entitlement keys. Static ldid validation proves only that the signature blob exists, CDHashes are extractable, and embedded entitlements match the configured plist. It does not prove RootHide/amfid acceptance or runtime permissions. Do not label the package device-verified until Sileo installation, cold launch, and post-reboot launch have been tested on the target RootHide device.

Rootless packaging is not produced by this RootHide script. Do not convert this RootHide package to Rootless; use a separately reviewed Rootless package profile if that target is later enabled.
