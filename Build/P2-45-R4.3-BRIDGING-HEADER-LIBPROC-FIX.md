# P2-45-R4.3 — 修复 Runner 编译：桥接头残留 `#include <libproc.h>` 导致 iOS SDK 头缺失

## Runner 环境

- 镜像 `macos-26-arm64`，Xcode 26.6，iPhoneOS 26.5 SDK，`-swift-version 5`，arm64 Release，`CODE_SIGNING_ALLOWED=NO`。
- 命令：`xcodebuild -scheme FilterKit -configuration Release -destination generic/platform=iOS ARCHS=arm64 ONLY_ACTIVE_ARCH=NO build`。
- 结果：exit 65，`** BUILD FAILED **`；`ZIPFoundation` 依赖包正常，失败仅在 `FilterKit` target 的桥接头依赖扫描阶段。

## 日志问题与定位

- `Sources/Features/Apps/FilterKit-Apps-Bridging-Header.h:2:10`
  - error（两次重复报出，同一根因）：`fatal error: 'libproc.h' file not found` / `bridging header dependency scanning failure`。
  - 根因：`libproc.h` 是 macOS 进程管理头，公开 iPhoneOS SDK 不提供；桥接头第 2 行 `#include <libproc.h>` 为历史遗留。
  - 对照 P2-31 既定口径：Swift 侧对 `proc_pidinfo` / `proc_bsdinfo` / `PROC_PIDTBSDINFO` / `pbi_pidversion` 等 libproc 符号的引用已全部删除（公开 Darwin SDK 不导出、无稳定可移植替代头），当前源码路径不再需要该头。

## 核对结论

- 全树无 `proc_pid` / `proc_name` / `proc_listpids` / `PROC_` 代码调用；`proc_uniqidentifierinfo` 仅出现在 `HelperPeerAuthenticationDiagnostics.swift` 的注释说明中，不产生头文件依赖。
- `DarwinPeerIdentityProvider.swift` 的 `getpid()` 由 Swift `Darwin`/`unistd` 模块提供，不依赖该桥接头。
- 其余 C/ObjC 头 include 仅 `UIKit/UIKit.h`、`objc/runtime.h`、`math.h`，均在 iOS SDK 内。

## 改动文件与目录

### `Sources/Features/Apps/FilterKit-Apps-Bridging-Header.h`（`Sources/Features/Apps/`）
