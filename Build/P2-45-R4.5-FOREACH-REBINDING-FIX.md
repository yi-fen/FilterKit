# P2-45-R4.5 — PluginsView ForEach 绑定重载歧义修复

## Runner 环境与结论
- 环境：`macos-26-arm64` / Xcode 26.6 / iPhoneOS 26.5 SDK / `-swift-version 5` / arm64 Release / `CODE_SIGNING_ALLOWED=NO`。
- Job run：`bddbe4c4-8983-5f13-ab07-627a99d72a6b`，exit 65，`** BUILD FAILED **`。
- 诊断：4 条 error，全部集中在 `PluginsView.swift:871-872`；上一轮 R4.4 的其余四类错误已不再出现。

## 归集诊断
- 871:21 `generic parameter 'C' could not be inferred`。
- 871:36 `cannot convert value of type '[PluginListStatus.AppEntry]' to expected argument type 'Binding<C>'`。
- 872:76 `cannot call value of non-function type 'Binding<Subject>'`。
- 872:90 `binary operator '??' cannot be applied to operands of type 'String?' and 'Binding<Subject>'`。

## 根因
- Swift 论坛同类案例表明：当 `ForEach` 内容闭包的类型检查受阻时，编译器会丢失元素类型推断，回退到 SwiftUI 的 Binding 重载（`init<C>(_ data: Binding<C>, content: (Binding<C.Element>) -> Content)`），把元素误判为 `Binding<AppEntry>`，于是产生误导性的 `Binding<C>` / `C could not be inferred` 报错；错误表象落在 ForEach 声明行。
- 上一轮为 `AppEntry` 补 `Identifiable` 未消除该歧义；本轮不再依赖元素协议遵循，改用编译器推断路径最稳定的 `Range<Int>` 下标重载，并把闭包内的 switch 控制流赋值移出 ViewBuilder 闭包。

## 改动文件与目录
1. `Sources/Features/Plugins/PluginsView.swift`
   - 关联 App 列表由数组元素重载改为 `entries.indices` 的 `Range<Int>` 下标重载：`let entries = status.apps` → `ForEach(entries.indices) { idx in let app = entries[idx] ... }`。`Range<Int>` 重载不要求元素 `Identifiable`，规避 Binding 重载歧义。
   - 注入状态键映射由闭包内 `switch app.injection { ... }` 提取为私有静态辅助方法 `injectionStateKey(_ injection: PluginListStatus.Injection) -> String`；闭包内改为 `let stateKey = Self.injectionStateKey(app.injection)`，消除 ViewBuilder 闭包内的控制流赋值。
2. `Sources/Features/Plugins/PluginListScope.swift`
   - 沿用上一轮 `AppEntry: Equatable, Identifiable`（`id = bundleIdentifier`），保留不改；entries 内 bundleIdentifier 已按归一化去重，id 唯一。
