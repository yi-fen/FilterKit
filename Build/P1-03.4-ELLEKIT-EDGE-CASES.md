# P1-03.4 — ElleKit edge cases and offline acceptance

## Scope

This phase remains read-only. It hardens the P1-03.1–P1-03.3 inspection pipeline; it does not install, modify, load, unload, or reconfigure ElleKit.

## Changes

1. **Overlapping Profiles:** the matcher no longer returns the first matching record. If more than one verified Profile matches the same package and binary evidence, the result is `ambiguous` and no Profile ID is selected.
2. **Conflicting binary candidates:** if one candidate matches a pinned Profile while another complete candidate conflicts, the result is `ambiguous`, not `matched`.
3. **dpkg database disagreement:** when `status` and `status-old` both contain installed ElleKit records but disagree on version or architecture, the current `status` record remains the primary source and a diagnostic warning is emitted. `status-old` is not promoted over current status.
4. **Identity versus source commit:** `profileIdentityVerified` means the observed package/binary fingerprint matched a pinned Profile. `commitVerified` is now always false because the collected fingerprint does not independently prove a source-control commit. A Profile's reference commit is metadata, not cryptographic provenance.
5. **Localization:** added matching Simplified Chinese and English diagnostics for database disagreement, conflicting binaries, and ambiguous Profile evidence.

## Outcome semantics

- `matched`: exactly one pinned Profile matches and there are no conflicting complete binary candidates.
- `ambiguous`: multiple Profiles match, or a matching binary coexists with a complete conflicting candidate.
- `identityMismatch`: complete available identity evidence conflicts with the applicable pinned Profile(s).
- `versionMismatch`: package identity is compatible but the dpkg package version is outside the Profile's allowed versions.
- `unknownFingerprint`: the applicable Profile is reference-only or has no verified binary pins.
- `unverifiable`: required evidence is missing or inaccessible.
