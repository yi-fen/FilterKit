# P1-34 — Trusted Helper Installer Provisioning & Lifecycle Plan

## Scope

P1-34 builds the signed-artifact hand-off and a closed install/upgrade/stop/start/uninstall/re-pin plan. It does **not** install anything on a device. The installer-facing API is validation/rendering only and has no filesystem mutation, ownership change, launchd invocation, or socket cleanup capability.

## Provisioning contract

`HelperInstallerProvisioningBundle` is the build/release pipeline hand-off. It requires:

- final App CDHash and final Helper CDHash as separate 40-hex inputs;
- bundle ID `cn.yfen.filterkit`, non-root App/staging UID, generation and release identifier;
- validated jbroot plus TweakInject and staging paths beneath that jbroot, a staging/TweakInject separation check, and the exact fixed Helper socket path;
- explicit route identifier and Helper version.

The dry-run requires syntactically valid SHA-256 inventory entries for the fixed Helper executable and launchd plist. It does not read those files or recompute their digests; a production installer must compare the staged bytes and independently verify the signed executable/CDHash. The model does not calculate or attest CDHashes. They must be collected after final signing by the trusted signing pipeline. A production root installer must independently verify the signed package/provenance and recompute the installed executable's kernel CDHash before activating it. A JSON artifact or hash string by itself is not a cryptographic signature or trust proof.

The bundle renders two complementary artifacts:

1. App-bundled `HelperAppTrustConfiguration`, containing the exact Helper CDHash only.
2. Root-owned `HelperDeploymentManifest`, containing exact App and Helper CDHashes, allowed non-root client UID, and `executionEnabled=false`.

The bundle also renders a conservative launchd plist with `Disabled=true`, `RunAtLoad=false`, and `KeepAlive=false`. No enabled plist is generated by this phase.

## Lifecycle transaction plan

`HelperInstallerTransactionPlan` supports install, upgrade, stop, start, uninstall and re-pin. Plans use fixed artifact locations and exact FilterKit launchd label; they do not accept arbitrary shell commands or destination paths.

- First install stages executable, launchd plist and manifest, verifies staged artifacts, then describes atomic activation. Failure cleanup is limited to FilterKit-owned staged artifacts.
- Upgrade/re-pin first stops the exact service and preserves the previous release. It stages and verifies the new release before activation. Rollback restores the previous release and leaves the service stopped.
- Start requires artifact verification and includes a socket verification step.
- Stop/uninstall target only `cn.yfen.filterkit.helper`. Socket removal is not authorized unless a future installer verifies it is a socket owned by root at the exact configured path.
- Uninstall is limited to FilterKit-owned executable, plist, manifest, audit and staging artifacts. It must not remove jailbreak components or package-manager files.

All plans set `mayRunFromApp=false` and `executionEnabled=false`.

## Runtime hardening

Helper startup now requires the socket path to equal `<jbroot>/Library/FilterKit/Helper/helper.sock`; the staging root must also remain under the validated jbroot. This narrows manifest path substitution. The socket's `0666` mode remains reachability only; every connection still requires kernel peer UID/PID/CDHash verification and session nonce binding. Device-specific socket-directory ownership and traversal behavior still require validation.

## Settings integration

Settings continues to show `Not configured` unless a verified App trust resource, a validated jbroot/socket location, and a production coordinator are explicitly supplied by the App composition root. P1-34 does not fabricate pins, infer the Helper CDHash, or silently connect to a guessed socket.

## Not implemented / not validated

- A privileged installer executable/package lifecycle hook that performs the plans.
- Cryptographic release provenance verification and signed provisioning-artifact verification.
- Actual post-signing CDHash extraction on iOS and installed Helper CDHash re-check.
- Root-owned manifest atomic installation/rotation and launchd bootstrap/bootout.
- Socket directory creation, ownership/mode enforcement, stale socket removal and lifecycle recovery.
- Settings composition-root injection and embedded trust resource delivery.
- Xcode/iOS SDK or Darwin build, XCTest execution, Dopamine RootHide/Rootless device validation.

No real Helper installation, launchd operation, TweakInject write, target App modification or re-signing was performed.
