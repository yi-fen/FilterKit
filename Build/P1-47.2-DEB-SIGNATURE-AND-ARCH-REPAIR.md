# P1-47.2 — DEB Installability: App Signature and Architecture

## Problem addressed

P1-47.1 packaged an Xcode product built with `CODE_SIGNING_ALLOWED=NO` directly
into a DEB. That could ship an app bundle without an embedded code signature.
It also accepted an `arm64e` build selection while the Debian package metadata
was hard-coded to `iphoneos-arm64`, allowing the package metadata and actual
Mach-O architecture to disagree.

## Changes

- Added `Build/Scripts/sign-ios-app.sh` to require an arm64 Mach-O slice, apply
  an ad-hoc signature to the staged app bundle, and verify it with `codesign`.
- DEB packaging signs the staged copy, not the build product or unsigned IPA.
- CI app builds now target arm64 for both arm64 and arm64e device labels. The
  report records requested device architecture separately from app ABI.
- Workflow architecture choices are limited to arm64 and arm64e labels; both
  produce an arm64 iOS app payload suitable for arm64e devices.
- Added a best-effort `uicache -p` post-install hook. Its failure is non-fatal.
- Extended the macOS packaging test to verify the embedded signature and arm64
  slice after extracting the DEB.
- Kept Rootless packaging blocked; this change does not infer RootHide path
  conversion or claim Rootless compatibility.

## Signing boundary

Ad-hoc signing does not require an Apple Developer certificate. It does not
create a publisher identity or grant platform/private entitlements. No
entitlements are added. The package still does not install the privileged
Helper.

## Validation

Shell syntax and static workflow/script checks are performed in this source
patch. The actual Apple `codesign`, `lipo`, Xcode build, Sileo install, and
SpringBoard launch must be validated on a macOS runner and target RootHide
jailbreak device. No Xcode build was run for this patch.
