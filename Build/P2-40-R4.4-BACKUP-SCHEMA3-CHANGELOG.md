# P2-40-R4.4 — Backup Schema 3 / Binding Topology

## Scope

Upgrade the FilterKit backup document to schema 3 so backup data can represent both:

- a plugin with an immutable fixed owner App;
- a plugin with no fixed owner and one or more additional App associations.

This phase is limited to backup export, codec validation, and restore preview data. It does not enable privileged restore or Helper writes.

## Changes

- `FilterKitBackupDocument.currentSchemaVersion` is now 3.
- `BackupPluginEntry.hardBoundBundleIdentifier` is optional for schema 3.
- Added `bindingTopology` as the authoritative schema-3 binding projection, including fixed-owner enabled state and each additional association's enabled state.
- Retained legacy fields as compatibility mirrors and reject mismatches.
- Schema 1 and 2 remain readable under their prior fixed-owner semantics; schema 2 still requires explicit additional-association states.
- Schema 3 requires a non-empty valid topology and a matching embedded manifest payload with verified SHA-256, plugin identity, filenames, file hashes, and binding projection.
- Backup export accepts schema-4 manifests with no fixed owner and preserves their topology in the backup.
- Restore preview no longer assumes a fixed owner exists. Missing fixed owners remain hard-blocking; missing additional Apps remain soft/missing-app notices.
- Updated restore review copy from hard-bound terminology to Fixed-owner terminology and added the additional-association-only label.

## Not performed / limitations

- XCTest suite was not executed.
- No RootHide/ElleKit device test was performed.
- `HelperDeploymentWriter` still stages only dylib and plist payloads; it does not yet deploy the backed-up manifest/topology. Restore remains review/staging-only and production mutation gates remain closed.
- Helper ownership verification, first-install authorization, and association mutation have not yet been upgraded to accept additional-association-only plugins.
