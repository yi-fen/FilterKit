# P2-45-R4.1 — Apple Device Build & Deployment Closure

## Scope

Prepare a reproducible macOS-only build/signing pipeline for the standalone `FilterKitHelper` executable and the `FilterKit.app` bundle. The pipeline uses one explicit Apple signing identity and Team ID, pins the final Helper CDHash into `FilterKit-Helper-AppTrust.json`, then signs the App with an installable provisioning profile.

## Changes

- Added `Build/scripts/p245_r4_1_apple_build_signing_closure.sh`.
- Added `Build/scripts/p245_r4_1_static_audit.py`.
- Build occurs in an isolated source copy; the user's working source tree is not modified by the macOS runner.
- Helper is built as an iPhoneOS executable, signed with the explicit Apple identity, and verified for identifier, Team ID and CDHash.
- The final Helper CDHash is embedded in the App trust resource before App signing.
- App signing requires an explicit Team ID, signing identity and device-installable provisioning profile; signature, profile Team ID, application identifier and artifact hashes are checked.
- No installation, launchd bootstrap/bootout, provisioning write, or production write-gate change is performed.

## Important unresolved runtime qualification

The current Darwin peer identity provider obtains the peer Team ID through `SecTaskCopyValueForEntitlement("com.apple.developer.team-identifier")`. The Helper signing pipeline must prove on the actual target iOS build and RootHide device that this value is present for the standalone Helper. A CodeDirectory `TeamIdentifier` line alone is not sufficient evidence that the entitlement API returns the same value. If it is absent, R4.1 must stop; do not weaken the identity policy or infer Team ID from CDHash.

The current XcodeGen Helper target still has `CODE_SIGNING_ALLOWED: NO`; the runner deliberately builds it unsigned and performs an explicit standalone codesign step. This is a controlled signing pipeline, not a change to the project-wide signing policy.
